# Lessons — Joint Chiefs

> High-bar, durable project rules only. One compact line each. Reviewed at session start.

## Rules

- 2026-05-28: Sign Joint Chiefs by certificate SHA-1 hash `E2EF8DBDD708A1857D5688F424272BE6821E463E`, never by name — two Developer ID certs share the identical name. After signing, hard-gate on `codesign -dv` showing `Authority=Developer ID Application` AND `TeamIdentifier=VJMJQKCRMC` before building the DMG. Never trust the build script's exit code as proof a signature took.
- 2026-05-25: Don't flag or churn docs solely because an exact test count changed. Prefer "90+ tests" or "see `swift test`" over exact numbers that age quickly.
- 2026-05-25: For Apple TV / wall-mounted dashboards, first control physical dominance: cap widget spans, reserve dead space, and test as a full-screen wall display. A widget that looks fine in a browser preview can be physically oversized on a mounted TV.
- 2026-05-25: Use `tasks/lessons.md` only for corrections and repeatable mistake-prevention rules — not for ordinary project context, access notes, or operating assumptions (those belong in `AGENTS.md`/`CLAUDE.md`).
- 2026-05-17: PR merged with placeholder cask sha because the real edit was never committed. A file edit is not in a release until committed. Before any merge or tag, require a clean `git status`. `gh pr merge` merges the remote branch, not your local working tree.
- 2026-05-17: Never run a destructive command (`rm`, overwrite) against a credential/state file in the same breath as a command that may have populated it (e.g. `migrate`, `write`). When smoke-testing a tool that writes to a real user-data path, `HOME` override does NOT isolate `FileManager.url(for: .applicationSupportDirectory)` on macOS — use the tool's explicit path-override parameter or back up first.
- 2026-05-17: For credentials read by headless or cross-session processes, use a `0600` permission-locked file (`~/Library/Application Support/Joint Chiefs/credentials.json`), not the macOS Keychain — the file-based keychain cannot be made prompt-free for automation. `CredentialStore` is the single source of truth; `LegacyKeychainStore` exists only for the one-time `keygetter migrate` path.
- 2026-05-16: For OpenAI chat-completions, do not send `temperature` or `top_p` — `gpt-5.x` reasoning models reject any non-default sampling params with a 400. Keep them `Double?` and omit when nil. Also use `max_completion_tokens`, not `max_tokens`. Verify a live call returns 200 when refreshing models, not just that the model appears in `/v1/models`.
- 2026-05-16: Headless Keychain reads silently fail on first access from a new process context — `errSecInteractionNotAllowed` is the actual error, not "not configured." CLI/MCP must distinguish these errors and report "Keychain needs approval" distinctly, pointing to the env-var path as the supported headless alternative.
- 2026-04-30: Never describe a pasted screenshot as "incidental," "unrelated," or "probable wrong-paste." Every image Chris pastes is intentional. If a Stash banner (`#XXXXXXXX`) is present, run the Stash pre-analysis BEFORE reasoning about the image.
- 2026-04-30: Do not quote `<90s` as a review-cycle performance expectation. A full hub-and-spoke debate across 4+ models (especially with a local model) runs minutes to tens of minutes. The `<90s` targets in `docs/ARCHITECTURE.md` and `docs/PRD.md` are stale — reconcile them. Anchor "stuck vs. working" diagnostics at minutes, not seconds.
- 2026-04-26: `CFBundleVersion` is the only thing Sparkle compares and must be a monotonically-increasing integer. Permanent floor: `1777000000` (v0.5.2). Increment by 1 per release. Never use `$(date +%s)`. Build script requires `JC_BUILD > JC_PREVIOUS_BUILD`. `sparkle:version` in appcast must match `CFBundleVersion` exactly — not the short version string.
- 2026-04-26: Website-Quickstart verification is a hard pre-tag checklist. Before tagging any release: verify every executable in `Package.swift` is in the `cp` command (index.html + download.html); MCP `command` path must be `/opt/homebrew/bin/` (Apple Silicon, never `/usr/local/bin/`); JSON-LD `softwareVersion` + announce-bar versions on all guide pages bumped; appcast `<item>` pushed atomically with other page edits.
- 2026-04-26: Pre-release doc scan must verify specific factual assertions in the README (spoke set, moderator framing, env-var table, CLI flags, test count, project layout, surfaces table, contributing roadmap) against shipping code, not just confirm the file is touched.
- 2026-04-26: Before any release, query each provider's `/v1/models` endpoint and update `availableModels` and `defaultModel` if a newer flagship has shipped. Also update per-provider `init(model:)` defaults, test assertions, CLAUDE.md "Default models" line, and README/ARCHITECTURE env-var tables.
- 2026-04-26: Before any release involving Apple services, confirm `date -u` matches `curl -sI https://www.apple.com` `Date:` header. `sudo sntp -sS time.apple.com` forces a sync even when `timed` is wedged. Auto-sync being "on" in System Settings doesn't guarantee the daemon is working.
- 2026-04-26: Every release requires a cold-machine smoke test before `gh release create`: (1) `rm -rf "/Applications/Joint Chiefs.app"`, (2) mount DMG, drag-install, (3) launch, (4) confirm process stays alive and first-run window appears. Signing and notarization verify identity, not runtime linkage. `build-app.sh` must run `install_name_tool -add_rpath "@executable_path/../Frameworks"` after copying Sparkle.
- 2026-04-23: Never create, commit, push, or delete any file that wasn't explicitly requested. Session handoff docs are internal (`tasks/SESSION-HANDOFF-*.md` is gitignored) — don't create them unprompted. "Let's tackle N" scopes to the technical work, not the release.
- 2026-04-23: **HARD RULE — never ship a release without explicit, in-the-moment permission and version-number confirmation.** A release is: any public git push bumping version metadata, any tag, `gh release`, appcast update, artifact upload, website download-button change, or cask version bump. "Just keep going" / "proceed" from earlier in the session is NOT release authorization. Release authorization is per-release.

The Part 4 checklist and Part 3 negative examples are hard constraints. Banned vocabulary (leverage, optimize, holistic, transformative, revolutionize, state-of-the-art, unlock, journey, empower, etc.) never appears — even in headings or IDs.

The enumerated list of providers the product calls (OpenAI, Gemini, Grok, Claude, Ollama) stays — those are features, not a compatibility assertion.
